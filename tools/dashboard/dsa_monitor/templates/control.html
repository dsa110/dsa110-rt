Fleet restart (cold recovery from stop)

Runs the full "broadcast stop → pkill dsart → wipe PSRDADA + shm → restart local systemd units → restart hiplot in LXC → re-spawn dsart_rt → defer self-restart of dsa_monitor" sequence. Excludes lxd110h20 entirely (grafana / influxdb / telegraf are never touched). The operator must press start + utc_start from the verb panel above once the orchestrators are back online — this button only puts dsart_rt back on the etcd watch line.

Audited to /mon/audit/control/<iso_ts> as cmd=restart_all with per-host pass/fail. The dashboard process will be killed by the deferred self-restart ~2 s after step 6 completes; the page will need a manual reload after that.

Signal injection (M7.4 Phase 6)

Pushes {cmd: "inject", val: <config>} to /cmd/dsart/corr/<chgroup>/inject for each selected chgroup. Each corr-fast service (launched with --inject-watch) picks up the PUT via its DsaStore.add_watch, validates the config, and calls OnlineInjector.add_pending. The injection is added in-place to the voltage tensor between unpack_int4_split and the RFI flagger, so the full corr → RFI → cal → gridder → coarse-DM → static-sky → transport → search → C2 chain sees it.

Leave apply_at_specnum blank for "as soon as possible" — the dashboard reads /mon/corr_rt/<cn>/corr_fast.block_specnum_start from every running corr_fast (published every 16 blocks by the M7.4 Phase 6c publisher) and arms the inject at max(block_specnum_start) + margin_blocks × NPACKETS_PER_BLOCK. Default margin {{ default_inject_margin_blocks }} blocks ≈ {{ '%.2f'|format(default_inject_margin_blocks * 2048 * 32.768e-6) }} s ahead of the fleet's current block_n at the chosen steady-state cubes/s rate.
Set target_snr to inject at a specific SNR; the dashboard reads the stored K for the (DM, width) bucket and derives fluence_jy_ms via fluence = width × (target_snr / K)². The fluence_jy_ms field is ignored when target_snr is set. If no K is stored for the bucket the inject returns 412 Precondition Failed — run the Calibrate panel below first.
Defaults shown produce a 50 Jy·ms / DM=500 / width=32- sample test pulse at boresight — good first smoke test once --inject-watch is active on the fleet.

Injection SNR calibration (M7.4 Phase 6c.A)

Fires one known-fluence probe at the chosen (DM, width) bucket and reads the resulting C1-candidate SNR back via /mon/dsart/inject/matches/<inj_id>. From that pair the dashboard computes K = observed_snr × √(width / fluence) and stores it at /cnf/inject/snr_calibration/<bucket>. Subsequent injections at a target_snr derive their fluence from this K.
Disable cube dumps with the dumps gate above before calibrating so that bright probes don't trigger the dump pipeline while you titrate the calibration.

Dump Now (one-shot diagnostic)

Captures the cube currently in flight on every search half. Use to inspect persistent RFI sources during commissioning. Sends a synthetic C2TriggerPacket (dumpnow_<rand>) to every (search_node, gpu_half) on the coinc.dump_broadcast fan-out list. The event_specnum is auto-picked a few blocks behind the fleet's latest block_specnum_start so the trigger lands inside every cube_ring's retention window — not too_late / too_early. NO production data-plumbing changes; this just feeds an extra UDP packet to the existing C2TriggerListener on each half.

Audited to /mon/audit/control/<iso_ts> as cmd=dump_now with per-half pass/fail. Each search-half ends up with a fresh dump under ${c1.dump_root}/<event_name>/cube_s<sid>_g<g>_<event_specnum>.npz. Refuses to broadcast (HTTP 503) if no /mon/corr_rt/<cn>/corr_fast publisher is answering.

Dumps Enabled (C2 broadcast kill-switch)

Flips /cmd/c2/dumps_enabled — the C2 coincidencer's runtime gate. When SUPPRESSED, C2 still runs the trigger criteria + writes the per-event archive row under /dataz/dsa110/candidates/<event>/ and emits a WOULD-DUMP … log line, but does NOT send the UDP fan-out into the per-half C1 listeners. Use during RFI bursts, fleet warmup, or any known-bad-data window to keep the audit trail without triggering downstream cube dumps. Default (missing key) is ENABLED (fail-OPEN) so a cold etcd never silently suppresses production dumps.
