Fringe-stopping tables (per-DEC cache)

meridian_fringestop refuses to start when its per-DEC fringe-stopping table is missing. Once it crashes, corr_slow blocks writing bada → the multi-reader fada ring deadlocks against corr_slow's stall → corr_fast hangs in getNextPage() ~300 cubes later. Build the cache file for the current pointing DEC before hitting Start. h23 keeps the master copy under <repo>/var/fstables/ (gitignored). Deploy rsyncs it to /home/ubuntu/data/fstables/ on every corr node. Builds run in casa38 on h23 via tools/build_fstable_cache.py --from-etcd (~4-5 min/DEC at nant=96).

DEC is snapped to the runtime grid step (0.25°, see meridian_fringestop_rt.snap_dec_to_grid) before the build script is invoked, so passing 54.5734 creates the table +54.5000deg. Synchronous; the dashboard worker blocks for ~4-5 min/DEC.

Signal injection

Pushes {cmd: "inject", val: <config>} to /cmd/dsart/corr/<chgroup>/inject for each selected chgroup. Each corr-fast service (launched with --inject-watch) picks up the PUT via its DsaStore.add_watch, validates the config, and calls OnlineInjector.add_pending. The injection is added in-place to the voltage tensor between unpack_int4_split and the RFI flagger, so the full corr → RFI → cal → gridder → coarse-DM → static-sky → transport → search → C2 chain sees it.

l/m limits: hard reject beyond ±0.0279 rad (imaged half-FoV — sources beyond it alias to the wrong position); recommended |l|,|m| ≤ 0.02 rad to stay within the primary beam (half-power ≈ 0.025 rad). 1 pixel = 0.000218 rad ≈ 45″.
Leave apply_at_specnum blank for "as soon as possible" — the dashboard reads /mon/corr_rt/<cn>/corr_fast.block_specnum_start from every running corr_fast (published every 16 blocks by the corr_fast publisher) and arms the inject at max(block_specnum_start) + margin_blocks × NPACKETS_PER_BLOCK. Default margin {{ default_inject_margin_blocks }} blocks ≈ {{ '%.2f'|format(default_inject_margin_blocks * 2048 * 32.768e-6) }} s ahead of the fleet's current block_n at the chosen steady-state cubes/s rate.
Set target_snr to inject at a specific SNR; the dashboard reads the stored K for the DM bucket (width-independent) and derives fluence_jy_ms via fluence = width × (target_snr / K)². The fluence_jy_ms field is ignored when target_snr is set. If no K is stored for the DM band the inject returns 412 Precondition Failed — run the Calibrate panel below first (any width pins K for the band).
Defaults shown produce a 50 Jy·ms / DM=500 / width=32- sample test pulse at boresight — good first smoke test once --inject-watch is active on the fleet.

Injection S/N calibration

Fires one known-fluence probe at the chosen DM and reads the resulting C1-candidate SNR back via /mon/dsart/inject/matches/<inj_id>. From that pair the dashboard computes K = observed_snr × √(width / fluence) and stores it at /cnf/inject/snr_calibration/dmNNNN. Subsequent injections at a target_snr derive their fluence from this K. K is width-independent post-fix — one probe at any width pins K for every width within the DM band; the width field below is just the probe's own pulse shape (informational metadata in the stored entry).
Disable cube dumps with the dumps gate above before calibrating so that bright probes don't trigger the dump pipeline while you titrate the calibration.

Dump Now (one-shot diagnostic)

Captures the cube currently in flight on every search half. Use to inspect persistent RFI sources during commissioning. Sends a synthetic C2TriggerPacket (dumpnow_<rand>) to every (search_node, gpu_half) on the coinc.dump_broadcast fan-out list. The event_specnum is auto-picked a few blocks behind the fleet's latest block_specnum_start so the trigger lands inside every cube_ring's retention window — not too_late / too_early. NO production data-plumbing changes; this just feeds an extra UDP packet to the existing C2TriggerListener on each half.

Audited to /mon/audit/control/<iso_ts> as cmd=dump_now with per-half pass/fail. Each search-half ends up with a fresh dump under ${c1.dump_root}/<event_name>/cube_s<sid>_g<g>_<event_specnum>.npz. Refuses to broadcast (HTTP 503) if no /mon/corr_rt/<cn>/corr_fast publisher is answering.

Dump control

C2 dumps (broadcast kill-switch)

Flips /cmd/c2/dumps_enabled — the C2 coincidencer's runtime gate. When SUPPRESSED, C2 still runs the trigger criteria + writes the per-event archive row under /dataz/dsa110/candidates/<event>/ and emits a WOULD-DUMP … log line, but does NOT send the UDP fan-out into the per-half C1 listeners. Use during RFI bursts, fleet warmup, or any known-bad-data window to keep the audit trail without triggering downstream cube dumps. Default (missing key) is ENABLED (fail-OPEN) so a cold etcd never silently suppresses production dumps.

Voltage dumps (C2 broadcast kill-switch)

Flips /cmd/c2/voltages_enabled — the C2 coincidencer's runtime gate for the corr-node voltage dumps (the DUMP_VOLTAGE UDP fan-out to all 16 corr nodes' voltage_retention readers). This is the expensive (~103 GiB/event) capability, separate from the cube "Dumps enabled" switch above. Injections never dump voltages regardless of this switch. Default (missing key) is DISABLED (fail-CLOSED) so a cold etcd or a fresh deploy never silently fills the corr-node NVMe staging — an operator must explicitly enable it here.

Reject mode (keep vs delete dumps)

Flips /cmd/c3/flag_only — the C3 collector's keep/delete mode, read per event. KEEP-ONLY (flag_only=true, the safe default) collects voltages and logs every cube-veto decision but performs NO destructive cleanup on rejected events. DELETE (flag_only=false) enables the conservative REJECT path: delete the staged voltages + bulky cubes/*.npz and MOVE the metadata/plots to candidates_rejected/<event>/ with a full audit — never an rm -rf. Injections and ambiguous events are always KEPT. Run KEEP-ONLY for the flag-first soak, confirm zero real losses, then switch to DELETE.

C3: …
Audited to /mon/audit/control/c3_mode_toggle/<unix_ms>. C3 re-reads the key on every event, so the new mode takes effect on the next candidate it processes.

Spectral-line mode (SPL)

Per sub-band (chgroup) toggle for spectral-line mode. When enabled for a sub-band, that corr node runs a second meridian_fringestop over the same bada slow-vis ring (which is created with r=2) and writes a finer-channelisation <UTC>_sb<NN>_spl.hdf5 product alongside the production slow-vis. When disabled, a no-op bada_null_drain holds the second reader slot so corr_slow never stalls. Config is written to {{ spectral_line_key }}; the orchestrators read it at start, so this takes effect on the next restart_all + Start fleet (it does not hot-swap a running fleet).

integration (s): SPL output integration time; converted to nint via the slow-vis cadence (tsamp = {{ spectral_line_state.tsamp_s if spectral_line_state.tsamp_s else 0.134217728 }} s). Leave at the default ({{ '%.3f'|format(spectral_line_state.default_integration_s) }} s, nint=96) to re-use the production fringe-table cache (no slow regen). nfreq_int: channels to average; must divide {{ spectral_line_state.nchan_spw if spectral_line_state.nchan_spw else 384 }} (nfreq_int=1 = full {{ spectral_line_state.nchan_spw if spectral_line_state.nchan_spw else 384 }}-channel resolution). Range {{ '%.3f'|format(spectral_line_min_integration_s) }}–{{ '%.0f'|format(spectral_line_max_integration_s) }} s.

Clear sidereal (l,m) dump vetos

Wipes the C2 sidereally-stationary dump-veto registry (/cnf/c2/sidereal_vetos, published for the Sky tab at /mon/c2/sidereal_vetos). These are sky positions that kept producing dump-worthy clusters (stationary RFI / continuum) and are currently suppressing dumps there. Clearing lets the registry re-learn from scratch — use it after mitigating an RFI source or if a real source was wrongly vetoed. Survives C2 restarts; this is the only way to reset it short of editing etcd.

Sends /cmd/c2/sidereal_vetos_clear; C2 applies it within one mon-publish tick (~5 s) and rewrites the registry empty. Requires the literal text clear_vetos.
