# `/mon/corr_rt/...` monitor-point schema reference

Author: realtime / search-node task M7.6 (May 2026)

This document specifies every monitor key under the `/mon/corr_rt/` etcd
prefix on the running M7.5 phase-B 16-corr / 4-search fleet. It is the
authoritative reference for any consumer that wants to bridge these keys
to a TSDB (InfluxDB, Prometheus, OpenTSDB, …), Grafana, an operator
dashboard, or an alert manager.

Companion docs:

* [`M7.6-MONITOR-POINTS-SEARCH.md`](./M7.6-MONITOR-POINTS-SEARCH.md) — `/mon/search_rt/*` schema
* [`M7.6-SERVICES.md`](./M7.6-SERVICES.md) — catalog of every M7.6 service (publishers + the new InfluxDB pusher + Grafana dashboard)

Three key shapes live under `/mon/corr_rt/`:

| key | cardinality | cadence | publisher | section |
| --- | --- | --- | --- | --- |
| `/mon/corr_rt/<cn>` | 1 per corr node (16) | 2 s | `dsart.services.dsart_rt.RtOrchestrator._publish_mon_dict` | [§2](#2-moncorr_rtcn--routine-rollup) |
| `/mon/corr_rt/<cn>/capture/<udp_port>` | 2 per corr node (32) | 2 s | `dsart.services.capture_control.CaptureControlService` | [§3](#3-moncorr_rtcncapture-udp-capture-counters) |
| `/mon/corr_rt/<cn>/rfi` | 1 per corr node (16) | 2 s | `dsart.services.rfi_monitor_export.RFIMonitorExportService` | [§4](#4-moncorr_rtcnrfi--rfi-flagger-window-summary) |

Plus one closely-related but slightly out-of-tree key:

| key | cardinality | cadence | publisher | section |
| --- | --- | --- | --- | --- |
| `/mon/service/corr_rt/<cn>` | 1 per corr node (16) | 2 s, lock-free | `RtOrchestrator._publish_heartbeat` | [§5](#5-monservicecorr_rtcn--heartbeat) |

The phase-B fleet has `cn_id ∈ {3, 4, 5, 6, 7, 8, 10, 11, 12, 14, 15, 16, 18, 19, 21, 22}` (16 cn ids; the gaps are search nodes 1, 2, 9, 13 and the unallocated 17, 20). Hostname stem is `n<NN>` zero-padded; FQDN over the back network is `n<NN>.pro.pvt`.

All values are JSON dicts written via `dsautils.dsa_store.DsaStore.put_dict` (etcd3 lease-less PUT). The etcd revision history is not relied on; consumers should treat each key as a tiny eventually-consistent record.

## 1. Conventions used in this document

- "field" = JSON key inside the payload dict.
- "tag" / "field" in the InfluxDB sense = see §6 for the recommended mapping.
- All times stamped by these publishers are UNIX epoch seconds or MJD (UTC-based). Where two are present, prefer `time_unix` for x-axis plotting.
- `cn_id` is **integer**, not "n03". Tag values for InfluxDB should be the integer string `"6"`, not `"n06"`; the host string is a separate tag.
- Cumulative-since-start counters carry the word `n_` (e.g. `n_recv_packets`); rate-derived gauges carry `rate_`; per-window averages have no prefix.
- "headline" metrics: the three M7.6-mandated ones, called out in §4.
- "schema_version" appears in the payload of §3 and §4. Bumped on any breaking schema change in this document.
- Tag rule of thumb: anything with **bounded low cardinality** (cn_id, host, udp_port, instance, arm_state, pol, detector) goes to tags; everything else to fields.

## 2. `/mon/corr_rt/<cn>` — routine rollup

Per-node summary of which child processes (dsart_rt routines) are alive
and which PSRDADA buffers exist. Written by the dsart_rt orchestrator
itself once per `mon_cadence_s` (default 2 s).

### 2.1 Payload schema

| field | type | tag/field | meaning |
| --- | --- | --- | --- |
| `cadence` | float (s) | field | mon-publish cadence (= 2.0). Useful as a divisor when computing rates over consecutive samples. |
| `time_mjd` | float | field | MJD timestamp at publish. Convert to unix via `(mjd - 40587) * 86400`. |
| `instance` | str | tag | dsart_rt config slot. Always `"pipeline_rt"` for corr_rt. |
| `cn` | int | tag | cn_id (3..22, gaps as above). |
| `host` | str | tag | publisher FQDN (`lxd110h06` etc.). |
| `state` | str | tag | orchestrator FSM state. Steady state: `"running"`. Other observed values: `"idle"`, `"starting"`, `"stopping"`, `"stopped"`, `"error"`. |
| `uptime_s` | float | field | seconds since `state` first transitioned to `running` in this orchestrator process. Restart of orchestrator resets to 0. |
| `routines` | `dict[str, {pid:int, alive:bool}]` | nested | per-child process status (see 2.2). |
| `buffers` | `dict[str, {key:str, metric:dict}]` | nested | per-PSRDADA-ring status (see 2.3). |
| `last_verb` | `{verb:str, val:int|str, age_s:float} \| null` | nested | last verb received over `/cmd/corr_rt/<cn>` or `/cmd/corr_rt/0`. `null` if none ever observed. |

If the orchestrator is mid-verb (e.g. a `start` is doing `dada_db -l` mlock for ~17 s), the **mon-dict publish is skipped** for that cycle. Heartbeat (§5) is lock-free and continues. Consumers must therefore tolerate a transient absence of fresh values: rate-derived alarms should use `>= 4 * cadence` (≥ 8 s) as the staleness window.

### 2.2 `routines` sub-dict

Eight named children on each corr node:

| routine name | C / Py | what it does |
| --- | --- | --- |
| `cap_a_real` | C bin | SNAP UDP capture, port 4011 → dada ring |
| `cap_b_real` | C bin | SNAP UDP capture, port 4012 → eada ring |
| `capture_control` | py | sidecar that publishes `capture/<port>` keys (§3) |
| `merge` | C bin (`dsaX_merge`) | merges dada + eada → fada |
| `corr_slow` | py | 1-s integrator off fada → bada |
| `bada_drain` | py | drains bada to disk / dev/null |
| `corr_fast` | py | M7.x fast-path integrator + RFI flagger (also feeds the rfi shm; see §4) |
| `rfi_monitor_export` | py | RFI mon sidecar (publishes §4) |

For each, the value is `{"pid": <int>, "alive": <bool>}`. `alive` is `proc.poll() is None`. A `False` here is the canonical "this routine died" signal — alert immediately.

### 2.3 `buffers` sub-dict

Four named PSRDADA rings: `dada`, `eada`, `fada`, `bada`. Each value is `{"key": <str>, "metric": <dict>}`. `metric` is parsed from `dada_dbmetric -k <key>` and is one of:

- **k=v dict** (newer PSRDADA build): `{"nbufs": int, "nfull": int, "nclear": int, "n_full_clear": int, "n_full_write": int, "n_read": int, "n_write": int}` — exact set varies by build.
- **CSV fallback** (older PSRDADA build): `{"raw_csv": str, "fields": list[str]}` — parse with care.
- **empty `{}`** (binary missing, timeout, parse fail) — current production state.

On the live fleet (May 2026) `metric` is always `{}` because `dada_dbmetric` is not on the orchestrator's `PATH`. Treat `metric == {}` as "no data" rather than "zero pressure"; do not emit InfluxDB points for empty metrics.

### 2.4 `last_verb` sub-dict

```
{
  "verb":  "utc_start" | "start" | "stop" | "utc_stop" | "reset" | ...
  "val":   int (specnum for utc_*; otherwise echo of the verb's payload)
  "age_s": float (= now - verb-receive-time, rounded to ms)
}
```

`age_s` is useful as a sanity gauge — a healthy fleet under steady state will show `last_verb.verb == "utc_start"` and `age_s` growing monotonically per node, all 16 with `age_s` within a few seconds of each other.

## 3. `/mon/corr_rt/<cn>/capture/<udp_port>` — UDP capture counters

Per-(node, UDP port) snapshot of the SNAP packet-capture binary's state and counters. Two keys per corr node — `4011` and `4012`. Published by the `capture_control` python sidecar (§2.2), which reads a 208-byte POSIX-shm segment (`/dsart-capture-<udp_port>`) written by the C capture binary `dsart_capture_manythread`.

The shm is updated by the binary's stats thread every ~100 ms and atomic-published every 2 s by the sidecar.

### 3.1 Payload schema

| field | type | tag/field | unit | meaning |
| --- | --- | --- | --- | --- |
| `schema_version` | int | field | – | currently `1`. Bumped on any breaking schema change. |
| `udp_port` | int | tag | – | `4011` or `4012`. |
| `control_port` | int | tag | – | `11223` (paired with 4011) or `11224` (paired with 4012). The orchestrator UTC_START/UTC_STOP UDP datagrams target this port. |
| `pid` | int | field | – | PID of the C capture binary. Changes on capture restart; treat as a hash. |
| `arm_state` | str | tag | – | enum: `"WAITING_FOR_ARM"`, `"ARMED"`, `"WRITING"`, `"STOPPED"`, `"UNAVAILABLE"`. Steady state: `"WRITING"`. |
| `arm_state_int` | int | field | – | numeric encoding: 0/1/2/3/-1 (UNAVAILABLE). Convenient for stacked-area plots. |
| `utc_start_specnum` | int | field | spec count | armed `utc_start` (echo of the verb). 0 if disarmed. |
| `utc_stop_specnum` | int | field | spec count | armed `utc_stop` (echo of the verb). 0 if open-ended. |
| `last_seq_no` | int | field | spec count | most-recent SNAP specnum seen on the wire (after the offset translation done by the binary). |
| `socket_rcvbuf_bytes` | int | field | bytes | effective `SO_RCVBUF` from `getsockopt`. Should be 512 MiB (= 536_870_912) in production. |
| `rate_gbps` | float | field | Gb/s | sliding-window receive rate. Healthy: ~8.4–9.7 Gb/s per port. |
| `rate_drop_mb_s` | float | field | MB/s | sliding-window dropped (kernel + payload + too-late) bytes/s. Healthy: < 1 MB/s; alert > 10 MB/s. |
| `rate_kernel_drop_pps` | int | field | pkts/s | sliding-window kernel-side drop pps (from `/proc/net/udp`). MUST be 0 in production; >0 means the bin is losing to SO_RCVBUF pressure. |
| `n_recv_packets` | int | field | counter | total UDP packets received since binary start. Monotonic. |
| `n_recv_bytes` | int | field | counter | total UDP payload bytes received since binary start. Monotonic. |
| `n_dropped_payload` | int | field | counter | packets the binary itself dropped (block-gaps + too-late). Monotonic. |
| `n_dropped_kernel` | int | field | counter | total kernel-side drops since binary start (`/proc/net/udp`). Monotonic; should be 0 in production. |
| `n_seq_skipped` | int | field | counter | gaps in seqno detected at the recv side. Monotonic. |
| `n_too_late` | int | field | counter | packets arriving after their block closed. Monotonic; small, non-zero is normal. |
| `n_wrong_size` | int | field | counter | recvfrom returned the wrong UDP payload size. Monotonic; alert any non-zero. |
| `n_recv_errors` | int | field | counter | `recvmmsg / recvfrom` errors (excluding EAGAIN). Monotonic; alert any non-zero. |
| `n_block_writes` | int | field | counter | full blocks written to the dada/eada ring. Monotonic; should advance ~7.45/s per port in steady state. |
| `startup_utc_ns` | int | field | ns | `clock_gettime(REALTIME)` at binary startup. Resets on binary restart. |
| `last_update_utc_ns` | int | field | ns | `clock_gettime(REALTIME)` at last stats-thread tick (~100 ms ago in steady state). |
| `age_ms` | float | field | ms | `(now - last_update_utc_ns)` at sidecar publish. Healthy: < 200 ms. Alert > 1000 ms. |
| `degraded` | bool | field | – | `true` iff sidecar detected the shm is stale (`age_ms > staleness_threshold_ms`, default 1000 ms) OR couldn't read the shm at all. |

If the C binary's shm is missing or has the wrong magic, the sidecar publishes a **degraded placeholder** instead of the full schema:

```json
{
  "schema_version": 1,
  "udp_port": 4011,
  "arm_state": "UNAVAILABLE",
  "arm_state_int": -1,
  "degraded": true,
  "shm_status": "missing" | "abi_mismatch" | "open_failed",
  "reason": "<short string>"
}
```

Consumers should detect this on `arm_state == "UNAVAILABLE"` (or equivalently `arm_state_int == -1`) and skip rate-derivative computations.

### 3.2 Cumulative-vs-gauge guidance for the TSDB pusher

The four `rate_*` fields are gauges already pre-derived by the C binary's stats thread (1-second EWMA-style window). Use them directly when you want sub-2-s temporal resolution.

The 9 `n_*` fields are cumulative-since-binary-start. Two complementary ways to consume them:

1. **Store the raw cumulative** and let InfluxDB compute deltas via `derivative()` / `non_negative_derivative()`. Robust against pusher restarts but produces large numbers. Recommended for `n_recv_packets`, `n_recv_bytes`, `n_block_writes`.
2. **Diff in the pusher** and emit deltas. Cheaper to query, but the pusher must track the last value per (cn_id, udp_port) and reset when `pid` changes. Recommended for `n_dropped_*`, `n_too_late`, `n_seq_skipped`, `n_wrong_size`, `n_recv_errors` (where you want a "events in last 2 s" gauge and counts since-startup is less useful).

Either way: **monitor `pid` for changes** and reset the per-(cn, port) state when it flips — counters reset on binary restart, and a naïve diff would produce a huge negative spike.

## 4. `/mon/corr_rt/<cn>/rfi` — RFI flagger window summary

Per-node aggregated RFI statistics for the latest sealed 16-cube window (≈ 2.147 s of voltage data). Written by the `rfi_monitor_export` sidecar (§2.2), which reads the on-node shm `/dev/shm/dsart-rfi-window-<cn>` produced by `corr_fast_integration`'s `RFIWindowAggregator`.

This is the **only** corr_rt key with nested `{pol0, pol1, both}` payloads — the rest is flat scalars.

### 4.1 Payload schema — envelope

| field | type | tag/field | meaning |
| --- | --- | --- | --- |
| `schema_version` | int | field | currently `1`. |
| `cn_id` | int | tag | corr-node id (3..22). |
| `time_unix` | float (s) | field | unix time at which the sidecar published this record. |
| `publish_unix` | float (s) | field | unix time at which `corr_fast` sealed the window and pushed it to shm. Wall-clock time for the right edge of the window. |
| `age_s` | float (s) | field | `time_unix − publish_unix`, rounded to ms. Healthy ≤ ~2.2 s. |
| `degraded` | bool | field | `true` when `age_s > staleness_s` (default 10 s) OR the corr-side producer disappeared. |
| `seq` | int | field | monotonic per-cn window sequence number. Wraps only at 2⁶³. Gaps ⇒ missed publishes. |
| `block_n_start` | int | field | first block index in this window. |
| `block_n_end` | int | field | last block index + 1. `block_n_end − block_n_start == n_cubes`. |
| `n_cubes` | int | field | always `16` once warmup is done; smaller during warmup. |
| `n_cubes_warmup` | int | field | of those, how many were still in flagger warmup (default 2 cubes ≈ 270 ms after `corr_fast` start). Steady state: `0`. |

### 4.2 Payload schema — metrics

Eight metrics; each is a dict `{"pol0": float, "pol1": float, "both": float}` where `both` is the unweighted mean across the two polarisations. Fractions are in [0, 1].

| field | meaning |
| --- | --- |
| `total_flag_fraction` | **HEADLINE** fraction of (ant, ch, t) triples flagged by *any* detector. |
| `bandpass_channel_fraction` | **HEADLINE** fraction of channels whose bandpass-outlier flag fired (per-channel boolean averaged across antennas at the cn level). Channels are post-4x freq-downsample (so 96 per cn-pol; the cn handles 96 antennas × 96 ch-ds × 2 pol per window). |
| `ant_fraction_flagged` | **HEADLINE** fraction of antennas that the group-outlier / SumThreshold detectors classified as whole-antenna-bad for this window. |
| `frac_sk` | fraction flagged by the spectral-kurtosis detector (`--sk-far`, default 1e-4). |
| `frac_bp` | fraction flagged by the bandpass-outlier detector (`--bandpass-k`, default 5.0). |
| `frac_grp` | fraction flagged by the group-outlier detector (`--group-k`, default 5.0). |
| `frac_sumthr` | fraction flagged by SumThreshold (`--sumthr-max-m 8 --sumthr-eta 1.5`). |
| `frac_fa` | fraction flagged by static `flagants.dat`. Constant per session. |

Detectors are mutually non-exclusive (a given sample can be flagged by SK *and* SumThreshold); `frac_*` taken **before** OR-ing into the final mask. Therefore `total_flag_fraction ≤ sum(frac_*)` and often `<<` it.

### 4.3 Suggested TSDB unfolding

Tag the polarisation explicitly to keep the field count down. For each window, emit one InfluxDB row per metric per pol:

```
measurement: corr_rt_rfi
tags:       cn_id, host, pol (pol0|pol1|both)
fields:     total_flag_fraction, bandpass_channel_fraction, ant_fraction_flagged,
            frac_sk, frac_bp, frac_grp, frac_sumthr, frac_fa,
            n_cubes, n_cubes_warmup, age_s, seq, block_n_start, block_n_end,
            degraded
time:       publish_unix
```

This gives Grafana 3-line plots straight from `WHERE cn_id='6'` queries.

### 4.5 Tuning knobs (driven externally)

The flagger knobs that move these metrics are CLI args on `corr_fast_integration`, pinned in etcd at `/cnf/pipeline_rt` (key `routines.corr_fast.args`):

```
--sk-far          1e-4    SK chi-squared false-alarm rate
--bandpass-k      5.0     MAD threshold for per-channel bandpass outliers
--group-k         5.0     MAD threshold for whole-antenna outliers
--sumthr-max-m    8       largest window in SumThreshold cascade
--sumthr-eta      1.5     SumThreshold scale parameter
--sumthr-disabled (flag)  set to disable SumThreshold entirely
--rfi-m-values    64,256,1024,4096   SK aggregation factors
--rfi-warmup-cubes 2      cubes excluded from publish during warmup
```

Edit `configs/dsart_pipeline_rt.yaml::routines.corr_fast.args`, push with `tools/ops/push_dsart_to_etcd.py --instance all`, restart `corr_fast`.

## 5. `/mon/service/corr_rt/<cn>` — heartbeat

Lock-free 3-field heartbeat published by the orchestrator alongside the §2 rollup. Kept in a separate key so that consumers can detect "orchestrator alive but mid-verb" — the rollup may be stale, but the heartbeat is *never* stale (it does not take the orchestrator's main lock).

| field | type | tag/field | meaning |
| --- | --- | --- | --- |
| `cadence` | float (s) | field | `mon_cadence_s` (= 2.0). |
| `time_mjd` | float | field | MJD timestamp at publish. |
| `state` | str | tag | same enum as §2: `running` / `idle` / `starting` / `stopping` / `stopped` / `error`. |

Use it as the *single source of truth* for "is the dsart_rt orchestrator on this cn alive". Threshold: alert if `now - mjd_to_unix(time_mjd) > 8 s` (= 4 × cadence) per cn.

```json
{"cadence": 2.0, "time_mjd": 61181.88644183713, "state": "running"}
```

This key lives under `/mon/service/...` rather than `/mon/corr_rt/...` because the same heartbeat shape is used by every long-running dsart-rt service (search_rt too).

## 6. Recommended InfluxDB pusher design

Below is a complete recipe for a sidecar that polls these keys and pushes to InfluxDB. It is intentionally prescriptive so the implementing subagent has minimal design freedom.

### 6.1 Polling

- One pusher process, on `h23` (same host as the dashboard).
- Cadence: **1 s** (twice the publish rate). Polling is cheap (etcd3 `get_prefix('/mon/corr_rt/')` returns ~64 keys ≈ 30 kB total).
- Track per-(key, modify_revision) so duplicate values aren't written: skip a key whose etcd `mod_revision` hasn't advanced since the last poll. (The `dsautils.dsa_store.DsaStore.get_etcd()` accessor gives you the underlying `etcd3` client; iterate `client.get_prefix('/mon/corr_rt/')` and read `meta.mod_revision`.)
- Decode payload with `dsautils.dsa_store.DsaStore._parse_value` or simply `json.loads(value.decode())`.

### 6.2 Measurements

Three measurements, one per key shape:

| measurement | from | tag keys | timestamp |
| --- | --- | --- | --- |
| `corr_rt_routine`  | §2 `/mon/corr_rt/<cn>` (rollup + per-routine + per-buffer expansion) | `cn_id`, `host`, `instance`, `state`, plus `routine` (when expanding `routines.*`) or `buffer` (when expanding `buffers.*`) | `mjd_to_unix(time_mjd)` |
| `corr_rt_capture`  | §3 `/mon/corr_rt/<cn>/capture/<port>` | `cn_id`, `host`, `udp_port`, `control_port`, `arm_state`, `pid` (or omit `pid` from tags — bounded by restarts but unbounded over time; safer as a field) | `last_update_utc_ns / 1e9` (or `time.time()` if missing) |
| `corr_rt_rfi`      | §4 `/mon/corr_rt/<cn>/rfi`, **fanned out by pol** (pol0, pol1, both) | `cn_id`, `pol` | `publish_unix` |

Per-routine expansion of §2: emit one `corr_rt_routine` point per (cn, routine_name) with tag `routine=<name>` and fields `{pid, alive (as 0/1 int), uptime_s, …}`. That way Grafana can graph "alive routines per cn" with `SELECT count(alive) WHERE alive=1 GROUP BY cn_id`. Optionally fold the `buffers.*` sub-tree into a second measurement `corr_rt_buffer` with tag `buffer=<k>` and fields = whatever non-empty `metric` keys arrive.

### 6.3 Handling cumulative counters

For each §3 cumulative field (`n_recv_packets` etc.), emit **both**:

- the raw counter as field `n_<field>` (so `derivative()` in InfluxQL/Flux works); and
- a pre-diffed delta `n_<field>_delta` computed in the pusher.

Reset the delta state whenever `pid` flips, OR whenever the new counter is *smaller* than the last seen counter (e.g. counter rollover). Emit `n_<field>_delta = 0` on the first sample after a reset; do not emit a negative spike.

State table key: `(cn_id, udp_port)`. State table value: `(pid, n_recv_packets, n_recv_bytes, n_dropped_payload, n_dropped_kernel, n_seq_skipped, n_too_late, n_wrong_size, n_recv_errors, n_block_writes)`. ~16×2 = 32 entries; trivial to keep in-memory.

### 6.4 Handling `degraded` / `UNAVAILABLE`

- For §3 placeholder records (`arm_state == "UNAVAILABLE"`): emit only the tag set + the `degraded=1` field. Do *not* emit synthetic zeros for `n_*`/`rate_*`; that pollutes the time series.
- For any §2-§4 record with `degraded == true`: still emit, but flag as `degraded=1`. Grafana templates should colour-code these.

```python
from dsautils.dsa_store import DsaStore
from influxdb_client import InfluxDBClient, Point, WritePrecision

KEY_CN          = re.compile(r"^/mon/corr_rt/(\d+)$")
KEY_CAPTURE     = re.compile(r"^/mon/corr_rt/(\d+)/capture/(\d+)$")
KEY_RFI         = re.compile(r"^/mon/corr_rt/(\d+)/rfi$")
KEY_HEARTBEAT   = re.compile(r"^/mon/service/corr_rt/(\d+)$")

ds = DsaStore()
client = ds.get_etcd()
influx = InfluxDBClient(url=..., token=..., org=...)
write = influx.write_api(write_options=SYNCHRONOUS)

state = {}  # (cn, port) -> dict for cumulative deltas

while True:
    points = []
    for value, meta in client.get_prefix('/mon/corr_rt/'):
        key = meta.key.decode()
        try:
            d = json.loads(value.decode())
        except Exception:
            continue
        m = KEY_CN.match(key)
        if m:
            points.extend(make_routine_points(d, cn=int(m.group(1))))
            continue
        m = KEY_CAPTURE.match(key)
        if m:
            points.extend(make_capture_points(d, cn=int(m.group(1)),
                                              port=int(m.group(2)),
                                              state=state))
            continue
        m = KEY_RFI.match(key)
        if m:
            points.extend(make_rfi_points(d, cn=int(m.group(1))))
            continue
    for value, meta in client.get_prefix('/mon/service/corr_rt/'):
        ...  # heartbeat
    write.write(bucket="dsa110", record=points)
    time.sleep(1.0)
```

## 8. Schema version policy

`schema_version` is **independent per key shape**. The values currently in production:

| key | `schema_version` |
| --- | --- |
| `/mon/corr_rt/<cn>` | (no `schema_version` field; backward-compatible additive changes only) |
| `/mon/corr_rt/<cn>/capture/<port>` | `1` |
| `/mon/corr_rt/<cn>/rfi` | `1` |
| `/mon/service/corr_rt/<cn>` | (no `schema_version` field) |

Rules for the InfluxDB pusher:

- **Additive change** (a new optional field): no `schema_version` bump. Pusher should gracefully ignore unknown fields.
- **Type change or rename**: requires `schema_version` bump in the publisher; pusher should *refuse* to ingest with a logged error if it sees a version it wasn't compiled for.

Whenever this document is updated to add fields, add them with a clear `(added 2026-...)` annotation in the table to ease pusher version reconciliation.
