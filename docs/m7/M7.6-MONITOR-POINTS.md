# M7.6 RFI monitor points in etcd

Author: realtime / search-node task M7.6 (May 2026)

Scope: every correlator node (`cn_id ∈ {3,4,5,6,7,8,10,11,12,14,15,16,18,19,21,22}`) publishes a single RFI summary record to etcd at

```
/mon/corr_rt/<cn_id>/rfi
```

every ~2 s, derived from a 16-cube window (≈ 2.147 s of voltage data) of the
production fast-path RFI flagger (`dsart.rfi.combine.RFIFlagger`).

The record is a flat-ish JSON dict written via `dsautils.dsa_store.DsaStore.put_dict`. It is sized so the dashboard (`tools/dashboard/dsa_monitor/`) and Grafana can each consume it without the full per-(ant, ch, pol) array payload — that lives on a per-node HTTP endpoint at `n<NN>.pro.pvt:5780` instead.

The publisher is the routine `rfi_monitor_export` (one per corr-node, sibling of `corr_fast`); see `configs/dsart_pipeline_rt.yaml` and `src/dsart/services/rfi_monitor_export.py`.

---

## 1. Envelope fields

| key | type | meaning |
| --- | --- | --- |
| `schema_version` | `int` | currently `1`. Bumped on any breaking schema change. |
| `cn_id` | `int` | correlator node id (matches `/mon/corr_rt/<cn_id>`). |
| `time_unix` | `float` | unix time at which `rfi_monitor_export` published this record to etcd. |
| `publish_unix` | `float` | unix time stamped by `corr_fast_integration` when the window was sealed and pushed into `/dev/shm/dsart-rfi-window-<cn_id>`. Used to compute age. |
| `age_s` | `float` | `time_unix − publish_unix`, rounded to 0.001 s. Should stay below `~2.2 s` in steady state. |
| `degraded` | `bool` | `true` when `age_s > staleness_s` (default `10 s`) or when the shm producer disappears. Signals "the corr-side has stopped delivering windows." |
| `seq` | `int` | monotonic per-cn window sequence number. Wraps only at 2⁶³, so effectively monotonic. Useful for detecting missed publishes (Grafana, dashboard). |
| `block_n_start`, `block_n_end` | `int` | first and last block index covered by this window. `block_n_end − block_n_start == n_cubes`. |
| `n_cubes` | `int` | always `16` once warm-up is complete. Smaller during warmup. |
| `n_cubes_warmup` | `int` | how many of those 16 cubes were still in flagger warmup (first `warmup_cubes` cubes after corr_fast start, currently `2` ≈ 270 ms). In steady state this is `0`. |

If `degraded == true`, downstream consumers should consider the cn unhealthy and skip averaging.

## 2. Headline RFI metrics

These three are the metrics explicitly requested for M7.6 (total flag fraction, bandpass-outlier channel fraction averaged across antennas, fraction of antennas flagged). Each is published as a `{pol0, pol1, both}` dict so XX and YY can be inspected independently — `both` is the unweighted mean across the two polarisations.

| key | type | meaning |
| --- | --- | --- |
| `total_flag_fraction` | `dict[str, float]` | window-averaged fraction of `(ant, ch, t)` triples flagged by *any* detector, separately for pol0 (XX), pol1 (YY), and `both`. Equals 1.0 when every voltage sample was flagged; ≈ 0.0 when none were. |
| `bandpass_channel_fraction` | `dict[str, float]` | per-window fraction of *channels* whose bandpass-outlier flag fired on the antenna-median bandpass. Averaged across antennas at the corr-node level (because the bandpass-outlier test runs on the ant-pol bandpass). Values O(10⁻³) — single bad RFI channels show up here. |
| `ant_fraction_flagged` | `dict[str, float]` | per-window fraction of antennas that the SumThreshold / group-outlier detectors classified as "this whole antenna is broken for this window." Values O(10⁻²) — typically 1–6 antennas out of 96 (≈ 1.0–6.3%). |

The dashboard's per-antenna table joins `ant_fraction_flagged` back to a per-antenna boolean (group-flag this window) by pulling the per-(ant, ch_ds, pol) mask via the HTTP endpoint.

## 3. Per-detector decomposition

These five tell you *which detector* did the flagging. They are mutually non-exclusive (a given sample can be flagged by SK *and* sumthr); they sum to ≥ the headline total. Each is again a `{pol0, pol1, both}` dict.

| key | source detector | what it catches |
| --- | --- | --- |
| `frac_sk` | spectral-kurtosis test against a chi-squared FAR threshold (`--sk-far`, default `1e-4`). | sample-level statistical outliers: short bursty RFI, narrowband CW lines, comb-like emitters. Dominant detector during high-RFI windows. |
| `frac_bp` | bandpass-outlier MAD test (`--bandpass-k`, default `5.0`). | persistent narrowband RFI (DME, GPS L3, S-DMB at 1.376–1.380 GHz). Per-channel boolean OR'd into the time axis, so `frac_bp` is the same per-channel constant within a window. |
| `frac_grp` | group-outlier MAD test (`--group-k`, default `5.0`) on the per-ant-pol total power. | whole-antenna outliers — saturated LNAs, bad receivers, antennas in motion. Drives `ant_fraction_flagged`. |
| `frac_sumthr` | SumThreshold (`--sumthr-max-m`, `--sumthr-eta`). | extended-duration / extended-bandwidth structure (drifting emitters, satellite passes). Operates on the SK statistic in time–freq. |
| `frac_fa` | static `flagants.dat` list applied at corr-fast start. | known-bad antennas. Constant per session unless the operator edits the list. |

Detectors are run in fixed order (SK → bandpass → group → SumThreshold → static flagants); the per-detector counts are taken *before* OR'ing into the final mask, so they reflect each detector's vote independently.

## 4. Cadence + retention

- Cadence: `rfi_monitor_export` polls its shm at `2 / window_period_s ≈ 1 Hz` and re-publishes whenever the sequence advances, subject to `--etcd-cadence-s` (default `2.0 s`). In steady state expect a fresh `seq` every ~2.15 s.
- Retention: etcd holds only the *latest* value (no key revisions inspected by consumers). 30 min of waterfall history lives on the corr-node HTTP server (`/api/recent?n=N`, default ring 64 slots ≈ 137 s) and on the h23 dashboard's in-memory ring (30 min, trimmed every poll).
- Wall-clock alignment: `publish_unix` is corrected for the `n_cubes` integration time; for Grafana plots, `time_unix` is the right x-axis.

## 5. Worked example

A typical low-RFI window (n06, normal sky):

```json
{
  "schema_version": 1,
  "cn_id": 6,
  "time_unix": 1779394750.893,
  "publish_unix": 1779394749.542,
  "age_s": 1.351,
  "degraded": false,
  "seq": 2143,
  "block_n_start": 34273,
  "block_n_end": 34288,
  "n_cubes": 16,
  "n_cubes_warmup": 0,
  "total_flag_fraction":     {"pol0": 0.237, "pol1": 0.127, "both": 0.182},
  "bandpass_channel_fraction":{"pol0": 0.003, "pol1": 0.001, "both": 0.001},
  "ant_fraction_flagged":    {"pol0": 0.073, "pol1": 0.052, "both": 0.063},
  "frac_sk":     {"pol0": 0.198, "pol1": 0.108, "both": 0.153},
  "frac_bp":     {"pol0": 0.003, "pol1": 0.001, "both": 0.002},
  "frac_grp":    {"pol0": 0.062, "pol1": 0.052, "both": 0.057},
  "frac_sumthr": {"pol0": 0.052, "pol1": 0.040, "both": 0.046},
  "frac_fa":     {"pol0": 0.031, "pol1": 0.031, "both": 0.031}
}
```

A worked example of a transient high-RFI window on the same cn (a bursty narrowband emitter hitting both pols):

```json
{
  "seq": 2536,
  "total_flag_fraction":     {"pol0": 0.982, "pol1": 0.998, "both": 0.990},
  "frac_sk":                 {"pol0": 0.937, "pol1": 0.988, "both": 0.962},
  "frac_sumthr":             {"pol0": 0.208, "pol1": 0.201, "both": 0.204},
  "ant_fraction_flagged":    {"pol0": 0.073, "pol1": 0.052, "both": 0.063}
}
```

`total ≈ 0.99` but `ant_fraction_flagged` stays at 6%: the flagger correctly identifies it as a wide-spectrum, narrow-time event rather than a hardware fault on specific antennas.

## 6. Suggested Grafana panels

| panel | y axis | source |
| --- | --- | --- |
| "Total flag fraction (16-cube window)" | `total_flag_fraction.both` per cn, stacked / overlayed | one line per cn |
| "Bandpass-outlier channel fraction" | `bandpass_channel_fraction.both` × 4096 = "bad channels" per cn | |
| "Fraction of antennas group-flagged" | `ant_fraction_flagged.both` per cn | high values ⇒ ant/receiver issue |
| "Detector decomposition" | stacked area of `frac_sk`, `frac_bp`, `frac_grp`, `frac_sumthr`, `frac_fa` for one cn | helps tune knobs |
| "Window age" | `age_s` per cn | should sit at ~1.0–2.2 s; alert > 5 s |
| "Degraded" | `degraded` per cn, count true | alert if > 0 for > 30 s |
| "Seq gap" | `derivative(seq)` per cn | should be ≥ 1 per ~2 s; gaps = missed publish |

## 7. Tuning knobs (out of band)

The flagger knobs that feed these metrics are exposed on `corr_fast_integration` CLI and pinned to etcd via `/cnf/pipeline_rt`:

```
--sk-far          1e-4    SK chi-squared false alarm rate
--bandpass-k      5.0     MAD threshold for per-channel bandpass outliers
--group-k         5.0     MAD threshold for whole-antenna outliers
--sumthr-max-m    8       largest window in SumThreshold cascade
--sumthr-eta      1.5     SumThreshold scale parameter
--sumthr-disabled (flag)  set to disable SumThreshold entirely
--rfi-m-values    64,256,1024,4096
--rfi-warmup-cubes 2      cubes excluded from publish during warmup
```

Edit `configs/dsart_pipeline_rt.yaml::routines.corr_fast.args`, then
`tools/ops/push_dsart_to_etcd.py --instance all`, then restart `corr_fast` (the
flagger constructor reads the values at routine start).

## 8. Service topology + verification

| host | service | port | etcd keys |
| --- | --- | --- | --- |
| each `n<NN>` | `corr_fast` (corr_fast_integration) | – | writes `/dev/shm/dsart-rfi-window-<cn>` |
| each `n<NN>` | `rfi_monitor_export` (sidecar) | 5780/tcp | publishes `/mon/corr_rt/<cn>/rfi` every ~2 s |
| `lxd110h23` | `dsa_monitor.service` (Flask, user unit) | 5778/tcp | reads `/mon/ant/<n>` only |

Verify on the live fleet:

```bash
# etcd:
python3 -c "from dsautils.dsa_store import DsaStore as S; import json
print(json.dumps(S().get_dict('/mon/corr_rt/6/rfi'), indent=2, default=str))"

# HTTP exporter (scalars + raw arrays):
curl -sS http://n06.pro.pvt:5780/api/health
curl -sS http://n06.pro.pvt:5780/api/latest | python3 -m json.tool | head -40

# Dashboard:
curl -sS http://lxd110h23:5778/antennas?ant=24
```

The dashboard is the human-facing consumer; etcd is the machine-facing consumer (alerting, Grafana, long-term storage outside of this codebase).
