# M7.4 Phase 6c — C1 Rate / C2 Latency / Cube-Dump Failure Diagnostic

**Date:** 2026-05-28 (mid-soak), unattended Phase 6c benchmark
**Author:** agent
**Soak window:** 14:12:12 → 14:52 (40 min) on the 16×4 fleet (corr_fast 16-way, search 4×2 halves)
**Trigger criteria config:** `configs/c2_trigger_criteria.yaml` unchanged from M7.3
**Search config:** `configs/dsart_search_rt.yaml` — c1.snr_min=8.0, c1.cube_ring_depth=8 (Phase 6c boot snapshot)

## TL;DR

C2 dump triggers fire correctly (43 DUMP events in 25 min, all `bright_frb_extragalactic`
or `bright_pulsar`) but **zero cubes are landing on `/dataz/dsa110/candidates/<event>/cubes/`**.
The search-side `C2TriggerListener` receives every trigger as `too_late`, with the
trigger's `event_specnum` thousands of slots behind the live `cube_ring` window.

Root cause: a stable on-sky RFI source at **DM ≈ 1655 pc/cc, snr_max ≈ 12.92** is producing
**~3000+ candidates per 5-s cluster window** at C2.  That candidate volume saturates the
C1→h23 emit TCP pipe, drives the per-half C1 emit queue into permanent overflow on the
hottest halves (n01-g0 dropped 7800 / 7815 batches = 99.8 %), and lags the C2 windowing
pipeline ≈ 25 s behind real-time.  By the time the matching UDP trigger reaches the search
node, the 8-slot cube ring (≈ 1.1 s of retention at 7.45 cubes/s) has rotated past the event
specnum and the listener correctly classifies it `too_late`.

The fix is two configuration lines (`snr_min: 8.0 → 12.0`, `cube_ring_depth: 8 → 16`); no
code change is needed.  Reasonable Phase 6c sensitivity is preserved because:

* `bright_galactic` already requires `snr_max_min: 12.0`.
* `bright_frb_extragalactic` advertises an 8 σ floor; raising the per-cand SNR threshold to
  12 σ only suppresses extragal triggers that ALSO failed the cluster-size and DM-IQR
  checks — i.e., the kinds of clusters that we were dropping all cubes for anyway.
* Phase 6c.A/B controlled injections at fluence ≥ 50 Jy·ms will produce per-cand SNRs ≫ 12.

Once the soak completes (≈ 14:52), the fleet will be relaunched with the patched
`dsart_search_rt.yaml` and the injection ladder re-run.

### 5. Cube-dump path itself is wired correctly

`SearchComputeService up (… dump=True … c2_trigger=True ring_depth=8)` on every half.  The
`C2TriggerListener` correctly binds to `10.41.0.205:11227 + gpu_half` per node, and the
dispatcher path `_handle_trigger → cube_dump.submit` is live.  The hit path simply never
fires because every trigger is `too_late`.

## Fix (Phase 6c boot config)

Two-line patch to `configs/dsart_search_rt.yaml`:

```yaml
c1:
  snr_min: 12.0        # was 8.0 (Phase 6c — kill RFI floor for commissioning)
  cube_ring_depth: 16  # was 8  (Phase 6c — widen retention to ~2.2 s)
```

* `snr_min: 12` halves to ~halves the cand volume per cluster window (most LOG windows had
  `snr_max ≤ 13`; once we cut at 12, the entire RFI bulge below is gone and only the rare
  bright tail survives).  Expected C1→C2 traffic drop: ≥ 50× based on the SNR distribution.
* `cube_ring_depth: 16` doubles the retention safety margin to ~2.2 s.  Memory cost:
  ~52 GiB pinned per gpu_half (104 GiB per 2-GPU search node), comfortably inside the
  256 GiB host budget.

No code change is needed; both knobs flow through the existing `c1_snr_min` and
`cube_ring_depth` plumbing in `src/dsart/services/search_compute.py`.

## Follow-up work (out of scope for this fix)

* **RFI mitigation** (Phase 6c.E zero-fill + NUMA-pinned imager).  Once the on-sky RFI
  source is masked or zero-filled at the imager, `snr_min` should be returned to 8.0 for
  production.  Tracked under M7.5 RFI hardening.
* **C2 windowing latency monitor** — add a mon-point for "wallclock − event MJD" at the
  trigger broadcast so we can alert before the ring rotates past triggers.  Currently we
  only catch this via the `too_late` warning, which fires too late.  Cheap to add.
* **C1 emit queue depth** — consider doubling `c1.emit_queue_depth: 16 → 32` for resilience
  against transient backpressure spikes during sky-source transits.  Memory cost is
  negligible.
* **Adaptive holdoff** — `bright_frb_extragalactic.holdoff_s = 30.0` means each dump path
  is gated for 30 s after firing.  For commissioning injects we may want to drop this to
  5 s.
