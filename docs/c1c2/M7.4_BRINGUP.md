## Acceptance criteria for M7.4

This pass is considered successful when **all of the following are true** :

1. **Detection** : at least one C1 candidate from at least one
   `(search_node, gpu_half)` half reaches C2 within the
   `coinc.window_s` (default 5 s) of the ground-truth MJD, with
     - `dm_pc_cc ∈ [395, 415]` (legacy 404.688 ± width-of-DM-trial),
     - `snr ≥ 9.0` (the C1 floor),
     - `width_samples ∈ {4, 8, 16}` (the ibox=3 boxcar maps roughly to
       the 8-sample matched filter in the new bank).
2. **Coincidence** : C2 emits a `bright_frb` (or at minimum
   `log_only`) cluster row containing the survivor(s); the cluster
   passes the `dm_iqr_max_pc_cc` and `n_search_nodes_min` thresholds
   in `configs/c2_trigger_criteria.yaml`.
3. **Naming** : the C2 service allocates an event name in the
   `260521xxxx` shape via `event.names.increment_name` (real or
   fallback allocator — the success criterion is that **only one**
   name is allocated for the burst, not that it shares the legacy
   namespace exactly).
4. **Dump trigger** : C2 broadcasts the `C2TriggerPacket` to all 8
   `(s, g)` C1 listeners; each listener that has the matching cube
   in its retention ring writes an NPZ under
   `${c1.dump_root}/<event_name>/cube_s<sid>_g<g>_<specnum>.npz`.
5. **Archive** : within 60 s of the broadcast, all 8 NPZs are
   rsync'd by `dsart_cube_uploader.service` to
   `/dataz/dsa110/candidates/<name>/cubes/`.  C2's plotter generates
   the 4 PNGs under `Level2/plots/`.
6. **Visualisation** : the new event shows up on the dsa_monitor
   "Burst candidates" tab (`http://lxd110h23:5778/burst_candidates`)
   with the 4 PNGs viewable, and on `http://lxd110h23:5017/`
   (HiPlot-C1) and `http://lxd110h23:5027/` (HiPlot-C2) within the
   next CSV rotation boundary (worst case ~1 h).

The legacy T2's SNR=30, DM=404.688, ibox=3 ground-truth lets us
quantitatively check the C1 detector (we expect SNR comparable to the
legacy detector's max-S/N kernel; an order of magnitude is fine if the
detector framing differs).

## Known fallbacks

  * **No C2 trigger fires** : likely the C1 SNR floor (9.0) is too high
    for the replay's reconstructed S/N.  Try lowering `c1.snr_min` to
    7.0 in the YAML and re-arming.
  * **Cube ring miss on broadcast** : the C2 trigger lookup arrived
    after the cube aged out of the ring.  Increase
    `c1.cube_ring_depth` (default 8) and re-arm; doc the memory
    trade-off.
  * **`event.names.increment_name` fails** : the fallback local
    allocator kicks in.  Verify by name shape (`local_<mjd>_<seq>` vs
    `260521xxxx`).
  * **HiPlot 502** : check that `casa38`'s `hiplot` binary is still
    at `/home/ubuntu/anaconda3/envs/casa38/bin/hiplot`; the new
    services use that path.
  * **Dashboard tab empty** : `tools/dashboard/dsa_monitor/app.py`
    must have re-imported `cands_panel_funcs.py` — `systemctl --user
    restart dsa_monitor.service`.
