# M7.4 — Phase 8: `dsa_monitor` Control tab

**Status: v1 PASS** (4 verbs: start / stop / utc_start / utc_stop).
Partial-restart + auto-arm are tracked as v2 follow-ups; both need
an additional `dsart-rt` orchestrator verb on the receive side
(see "Open work" below).

## Goal

Expose the `dsart-rt` orchestrator command surface
(`/cmd/{corr_rt,search_rt}/<cn>` keys with `{cmd, val}` payload)
from the existing `dsa_monitor` Flask dashboard on `h23`, so a
familiar operator workflow ("Start fleet → arm → … → disarm →
stop") can be driven from a browser instead of a shell + the
ad-hoc one-liner ops scripts.

The Phase-8 inventory established that the fleet already has all
the *receive* side: every `dsart_rt` instance has a
`_handle_command_event` loop watching its `/cmd/<ns>/<cn>` key
(plus the corr-side broadcast on cn=0). The Control tab is just a
write-side affordance on top of `dsautils.dsa_store.DsaStore`.

## Architecture

```
browser  ──POST──>  Flask /control/{verb}  ──ControlStore──>  etcd
                       │                                         │
                       │                                         │
                       └── audit_log() ──put_dict()──>  /mon/audit/control/<iso-ts>
                                                                 │
                                                                 ↓
                                                  every dsart_rt orchestrator's
                                                  watch picks up the new cmd
                                                  on /cmd/<ns>/<cn>
```

Three modules — all under `tools/dashboard/dsa_monitor/`:

| File | Purpose |
| --- | --- |
| `control_store.py` | New. `ControlStore` (DsaStore wrapper) + verb senders + `compute_arm_seq` + `audit_log` + high-level helpers (`control_start_fleet`, `control_stop_fleet`, `control_utc_start_now`, `control_utc_stop_now`). Bit-identical payload shape to `tools/ops/_m75_phaseB_16x4_launch.sh`. |
| `templates/control.html` | New. Two-column layout: fleet-readiness panel (next ARM_SEQ candidate, capture mon-key health) + verb buttons (start / arm-now / disarm / stop) + bottom audit-log table. Inline JS POSTs to the Flask routes and reloads after 1.5 s so the audit row shows up. |
| `app.py` | Modified. Six new routes (`GET /control`, `POST /control/start`, `POST /control/stop`, `POST /control/utc_start`, `POST /control/utc_stop`, `GET /control/recent_audit`). Each POST runs through `_control_json_or_error` which catches exceptions, audits the failure, and returns a JSON error so the UI doesn't 500 on a transient etcd hiccup. |

### Payload shape — bit-identical to ops scripts

```python
{"cmd": "start", "val": 53.85}      # control_start_fleet
{"cmd": "stop", "val": None}        # control_stop_fleet
{"cmd": "utc_start", "val": 12345}  # control_utc_start_now (ARM_SEQ)
{"cmd": "utc_stop", "val": 12345}   # control_utc_stop_now
```

Written to:

* `/cmd/corr_rt/0` — broadcast (corr-side; every corr_rt orchestrator
  watches cn=0 in addition to its own cn).
* `/cmd/search_rt/{1,2,9,13}` — per-cn fanout (search_rt has no
  broadcast in the current `dsart_pipeline_rt.yaml`, so we PUT to
  each of the four search nodes individually).
* `/cmd/corr_rt/{3..22}` — per-cn fanout, only on `stop`
  (belt-and-braces so a node that missed the broadcast clears
  independently). Toggleable via `fanout_corr_too=False` on the
  POST.

### ARM_SEQ computation

`compute_arm_seq` walks the 32 capture mon-keys
(`/mon/corr_rt/<cn>/capture/<port>` for cn ∈ {3..8, 10..12, 14..16,
18..19, 21..22} × port ∈ {4011, 4012}), reads `last_seq_no` from
each, and returns `max(last_seq_no) + margin`. Default margin is
30 000 specnums (~0.98 s) which matches Phase-A single-cn ops; the
UI lets the operator bump it (Phase-B fleet typically uses 60 000
to absorb wider clock skew, per
`tools/ops/_m75_phaseB_16x4_launch.sh` Stage 5).

The function **refuses** to compute an ARM_SEQ if no captures
answer — `control_utc_start_now` then returns `{ok: False, error:
"no captures answering — refusing to broadcast a blind utc_start"}`
and writes an `ok=False` audit row. The UI surfaces this as a red
"FAIL" banner with the JSON payload inline.

### Auditing

Every verb (success or failure) writes a `ControlAction` to
`/mon/audit/control/<iso-ts>`. The row carries:

| Field | Source |
| --- | --- |
| `iso_ts` | UTC, microsecond resolution (also the etcd key suffix) |
| `user` | POST form field if present, else `request.remote_addr` |
| `host` | `socket.gethostname()` (so we know which `h23` proxy if there's more than one) |
| `namespace` | `corr_rt+search_rt` (or just `corr_rt` for ARM verbs) |
| `cn_target` | `0`, `0+1,2,9,13`, `0+all+1,2,9,13` — describes the fanout |
| `cmd`, `val` | Exact verb shape sent |
| `ok` | True on success, False on either `error` return or exception |
| `note` | Free-form (e.g. ARM_SEQ derivation, exception repr) |

The audit log is the proof-of-control surface — there's no
end-user authentication in v1 (network ACL on `h23` only); see
"Security posture" below.

## Security posture (v1)

* **Network-only.** `dsa_monitor` is bound to the `h23` internal
  interface and only reachable from the DSA-110 NUC + dedicated
  operator workstations. There is no per-user auth.
* **Two safety speed bumps** on the most-destructive verb:
    * `POST /control/stop` requires `confirm=stop` in the form body
      (the template renders a small text input).
    * The "Stop fleet" button is red (`.danger` CSS class).
* **`utc_start` refuses to fly blind.** If `compute_arm_seq`
  returns no answering captures, the verb is *not* broadcast — the
  UI shows a red FAIL banner instead of silently sending
  `val=None`, which the orchestrator would reject anyway. The
  refusal is audited.
* **Audit log is mandatory.** Even if `put_dict` for the audit row
  fails (etcd timeout), the verb itself is unaffected — the audit
  failure is logged to `dsa_monitor`'s Python logger but the verb
  still gets sent. We never lose the verb to preserve auditability.

A future revision (v2) is expected to add reverse-proxy auth +
per-action 2FA on the destructive verbs; the
`DSA_MONITOR_USER` env var path is already plumbed through
`audit_log` so a reverse proxy can inject the authenticated user
header without touching `control_store.py`.

## Tests

`tests/test_dsa_monitor_control_store.py` — **26 cases, all
passing**:

| Test class | What it covers |
| --- | --- |
| `TestSendVerb` | Canonical key (`/cmd/{ns}/{cn}`), payload shape (`{cmd, val}`), namespace allowlist, `val=None` handling. |
| `TestBroadcastCorr` | `cn=0` broadcast goes to `/cmd/corr_rt/0` exactly once. |
| `TestFanoutSearch` | Default hits all 4 search cns (1, 2, 9, 13); custom subset honored. |
| `TestFanoutCorr` | Default hits all 16 corr cns (3..8, 10..12, 14..16, 18..19, 21..22). |
| `TestComputeArmSeq` | Walks all 32 capture keys; returns None when no captures answer; max-wins across the fleet; honors custom margin (Phase-B 60 000); skips non-dict payloads. |
| `TestAuditLog` | ISO-8601 UTC key; payload carries user/host/cmd/val/ok/note; audit failures are swallowed (don't break the verb). |
| `TestControlStartFleet` | 1 corr broadcast + 4 search fanout + 1 audit = 6 writes; dec passes through; `None` dec stays `None`. |
| `TestControlStopFleet` | With `fanout_corr_too=True` (default): 1 broadcast + 16 corr fanout + 4 search fanout + 1 audit = 22 writes; with `False`: 6 writes. |
| `TestControlUtcStartNow` | Refuses when no captures answer (audit row, `ok=False`); broadcasts ARM_SEQ on success. |
| `TestControlUtcStopNow` | Sends `utc_stop` with current ARM_SEQ + 0 margin; falls back to `val=0` when no captures answer. |
| `TestTopologyConstants` | Corr cn count == 16, search == (1,2,9,13), capture ports == (4011,4012), no cn overlap between corr and search lists. |

In addition, the Flask routes were smoke-tested via
`app.test_client()` against a `FakeDsaStore`:

* `GET /control` returns 200 with "Fleet Control", "Start fleet",
  "Arm now", "Stop fleet" rendered.
* `POST /control/start` (no dec) returns the broadcast + 4 fanout
  keys.
* `POST /control/stop` without `confirm=stop` returns 400.
* `POST /control/stop` with `confirm=stop` returns 200 + 22 writes.
* `POST /control/utc_start` (no captures) returns `ok=False` with
  the refusal message.
* `POST /control/utc_stop` returns 200 with `val=0` (no captures
  → 0 fallback).

All four other tabs (`/`, `/antennas`, `/sefds`, `/bursts`) still
render 200 and now include the new "Control" link in the nav bar.

## Open work (Phase 8 v2)

1. **Partial-restart verb.** Per-cn restart needs a new orchestrator
   verb (`restart` on the receive side); the dashboard scaffolding
   (per-cn checkbox list) is ready but not exposed. Track as
   `phase8_v2_partial_restart`.
2. **Auto-arm.** A periodic background task that watches for the
   capture mon-keys reaching steady state and self-broadcasts a
   `utc_start`. The `control_utc_start_now` function is reusable
   from a `threading.Timer` callback; the wiring (timer registration
   + UI toggle + persisted state) is v2.
3. **Reverse-proxy auth.** Add an `Authorization: Bearer …` check
   on the POST routes (read from
   `tools/dashboard/dsa_monitor/auth.py` — to be created) so
   per-user auth is on a real cryptographic surface, not just a
   network ACL.
4. **WebSocket audit stream.** Today the audit panel refreshes via
   page reload (1.5 s after each verb). A WebSocket subscription on
   `/mon/audit/control/` would push new rows live; cheap with
   etcd's native watch.
